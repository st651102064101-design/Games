# Frostline: combat, touch controls and pet revival

ปรับจาก `Frostline_v3_4_holes.html` ใน commit `dca3b4f` ของ Games

## สิ่งที่เปลี่ยน

- ซูมเริ่มต้น 1.0 → 0.6 และรีเซ็ตเมื่อเริ่มรอบใหม่
- เลือดเริ่มต้น 125 → 250 รวมถึงเพิ่มเลือดจากเกราะและเลเวลเป็นสองเท่า บอตใช้เลือด 240 และเลิกบังคับตายเมื่อโดนครบสองครั้ง
- ตรวจการชนตลอดแนวดาบถึงปลายที่วาดจริง พร้อมตรวจช่วงที่ดาบกวาดระหว่างเฟรม ผู้เล่นไม่มีอาวุธจึงรับดาเมจเมื่อปลายดาบแตะตัวได้
- กระสุนแต่ละนัดที่โดนผู้เล่นซึ่งยังมีดาบประชิดหมุนอยู่ ทำลายดาบหนึ่งเล่มโดยไม่หักเลือด กระสุนห้านัดในเฟรมเดียวจึงใช้ดาบห้าเล่ม; นัดถัดจากดาบหมดจึงเริ่มทำดาเมจ ระเบิด RPG ใช้กติกาเดียวกัน อาวุธที่แตกเป็นเอฟเฟกต์ ไม่กลายเป็นไอเทมให้เก็บซ้ำ
- หมาเข้ามาชุบชีวิตครั้งแรก จากนั้นล้ม เรืองแสง และหายไป มีสิทธิ์ชุบเพียงครั้งเดียวต่อรอบ
- ส่งตำแหน่งหมา ขนาดตัว และสถานะล้ม/ชุบ/ฟื้น/ตาย ผ่านทั้ง P2P และ HTTP relay ผู้เล่นอื่นใช้แอนิเมชันตัวละครและเอฟเฟกต์แสงเดียวกัน ปฏิเสธแพ็กเก็ตสถานะที่ย้อนลำดับ
- ตัวเลขอาวุธใช้ขนาด 22.5 px จากเดิม 15 px (1.5 เท่า) และคงความอ่านง่ายเมื่อซูมออก ป้ายใต้ตัวแสดง `คุณ`/`You` หรือชื่อของผู้เล่นอื่น แม้ใช้กราฟิกต่ำ
- ลากสองนิ้วปรับมุมกล้อง 0–90°; ถ่าง/หุบปรับซูมแยกกัน นิ้วที่ลากเดินยังทำงานขณะอีกนิ้วแตะสองครั้งเพื่อวาร์ป
- ลดโอกาสสร้างไอเทมทุกชนิดลง 50% ณ ไคลเอนต์ที่ดูแลของดรอป ไม่สุ่มซ้ำตอนส่งให้คนอื่น รวมของจากบอส แอร์ดรอป กองอาวุธ วัตถุดิบ และ XP ส่วนอาวุธเริ่มต้น/ที่ซื้อไว้ไม่ใช่ของดรอป
- เพิ่มการเอนตามความเร็วและความเร่ง การยุบ/คืนตัวด้วยสปริงหน่วงให้ทุกสกินและสัตว์ หมาเร่งและเบรกตามแรงเฉื่อย ปืนมีแรงถีบกลับ อาวุธที่แตกกระเด็นตกและเด้งตามแรงโน้มถ่วง

## การติดตั้ง

นำไฟล์ใน ZIP ไปแทนที่ไฟล์ใน repository ตามโครงสร้างโฟลเดอร์เดิม แล้ว build/deploy ตามปกติ ต้องอัปเดต relay ของโฮสต์ที่ใช้งานด้วย:

- Netlify: `netlify/functions/frostline-pvp.mjs`
- EdgeOne: `edge-functions/api/frostline-pvp.js`

เปลี่ยนเฉพาะ HTML อย่างเดียวจะยังไม่ได้ข้อมูลหมา/ตาย/ฟื้นผ่าน HTTP relay รุ่นเก่า ผู้เล่นทั้งสองฝั่งควรโหลดหน้าเวอร์ชันใหม่

ไฟล์ HTML ยังอ้างอิงเสียงเดิมใน repository จึงควรเก็บไฟล์เสียงไว้ในโฟลเดอร์เดิม

## การทดสอบ

```sh
npm install
npx playwright install chromium
npm run test:frostline
npm run build
```

หากใช้ Chromium ที่ติดตั้งไว้เอง ตั้ง `CHROMIUM_PATH` เป็น path ของ browser ได้ ชุดทดสอบใช้ Chromium สอง browser contexts และ HTTP relay จริงของโปรเจกต์ร่วมกับ storage ในหน่วยความจำ รวมถึงส่งเหตุการณ์ multi-touch ผ่าน Chrome DevTools Protocol ไม่ต้องติดต่อผู้เล่นจริง

ตรวจ 15 กลุ่ม: เลือด/ซูม, กระสุนห้านัด, RPG, ปลายดาบ/ดาบกวาดเร็ว, ของดรอปทุกชนิด, วาร์ประหว่างเดิน, ทัชแบบ native, กล้อง/ซูม, ป้ายชื่อ, การวาดทุกสกิน/สัตว์ 50 ชนิด/อาวุธ 30 แบบ, ความเสถียรฟิสิกส์ที่ 30/120 Hz, หมาและชุบชีวิตข้ามเซสชัน, การตายครั้งที่สอง, สถานะย้อนลำดับ และท่าทางสองนิ้วเดิม นอกจากนี้ตรวจ sanitization ของ relay ทั้งสองโฮสต์ เสียง และ static build

ชุดเก่า `frostline-runtime.cjs` และ `frostline-arsenal.cjs` มีปัญหาตั้งแต่ commit ต้นทาง: ชุดแรกเลือก script ป้องกัน view-source แทน script เกม ทำให้ไม่มี `testApi`; ชุดหลังไม่ได้กำหนด `world` ใน VM จึงใช้ชุด browser integration ใหม่ตรวจการเล่นจริงแทน

## ขอบเขต

เกมเดิมเป็น Canvas 2D: กล้อง 0–90° ใช้การฉายภาพ 2.5D โดยรักษาตัวละครให้ตั้งตรงและคงความลึกของพื้นขั้นต่ำเพื่อให้เดิน/วาร์ปเลือกตำแหน่งได้ ไม่ใช่กล้อง 3D ที่มี perspective และฉากสามมิติ ฟิสิกส์เป็นแบบจำลองเบา ๆ สำหรับเกมนี้ ไม่ใช่ rigid-body engine เต็มรูปแบบ

ทดสอบการรับส่งด้วย relay และ storage จำลองในเครื่อง ยังไม่ได้ deploy หรือทดสอบกับ Netlify/EdgeOne production
